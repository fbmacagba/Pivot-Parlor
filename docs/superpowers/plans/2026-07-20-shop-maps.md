# Shop Maps from Address Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the Google Maps embed on shop sites actually render for shops that have an address but no coordinates (every real shop), and add "Get directions" links on the location sections and the booking confirmation screen.

**Architecture:** A new `googleMapsEmbedUrl(query)` helper in `@repo/utils` builds an address-based `output=embed` URL. The two location section components fall back to it when `lat`/`lng` are absent (coordinates remain a precision override), and both gain a "Get directions" link. A small new `BookingConfirmMap` component (map + directions button) is rendered on the confirmed state of the booking confirmation route when the shop layout provides an address.

**Tech Stack:** React (Remix on Cloudflare Pages), vitest + jsdom with `renderToStaticMarkup`, Tailwind classes over `--st-*` theme tokens.

**Spec:** `docs/superpowers/specs/2026-07-20-shop-maps-design.md` (approved). Branch: `feat/shop-maps` (already exists, branched off main; the spec commit is on it).

## Global Constraints

- Colors via `--st-*` / `--color-*` tokens only. Never hardcode hex/rgba in the new markup.
- Every new interactive element is a 44px+ touch target (`min-h-11` on links; `size="lg"` on `ThemedButton`, which is h-12).
- No em-dashes in user-facing text.
- No new dependencies, no migrations, no worker changes, no changes outside `apps/web` + `packages/utils`.
- Do NOT touch `packages/utils/src/designSpec.ts` (byte-compare-guarded sync copy exists elsewhere).
- The parity suite (`apps/web/app/components/site/renderParity.test.tsx`) and seeded sweep (`seededSweep.test.tsx`) must stay green. Both legacy and v3 paths render the same section components, so section changes apply to both sides at once; do not add any `design_version` gate.
- Coordinates embed URL stays byte-identical to today: `` `https://www.google.com/maps?q=${lat}%2C${lng}&z=15&output=embed` ``.
- The address embed URL is exactly `https://www.google.com/maps?q=<encodeURIComponent(query)>&output=embed`; the directions link uses the existing `googleMapsUrl` (`https://www.google.com/maps/search/?api=1&query=...`). Always pass the BARE address, never a business-name prefix (documented gotcha: a name prefix degrades to a pinless search view).
- `$shopSlug.confirm.tsx`: change ONLY the confirmed state. The settling and cancelled states, the loader, and `ConfirmShell` are untouched.
- Test-assertion gotcha: `renderToStaticMarkup` HTML-escapes `&` in attribute values, so URL assertions must expect `&amp;` (e.g. `...London&amp;output=embed`).
- Windows shell: run commands from the repo root `F:\Projects\Pivot Parlor\pivot-parlor` with `cd` into the workspace as shown; git identity is already configured (`gh auth switch --user fbmacagba` before any `gh` call).
- Commit style: conventional commits (`feat(site): ...`), each ending with the `Co-Authored-By: Claude Fable 5 <noreply@anthropic.com>` trailer.
